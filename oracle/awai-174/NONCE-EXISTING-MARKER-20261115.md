# Read-only nonce replay against an existing marker — 2026-11-15

`nonce-store/consumer` first reads the scoped nonce ref. If present, it requires the expected marker CID, reads and structurally verifies that marker, then returns false without a block write. If absent, it keeps the existing put, readback and CAS sequence; a concurrent successful CAS still makes the loser return false. A foreign ref or absent/corrupt marker is refused. This does not provide anti-rollback, distributed fencing or a transaction with a receipt.

A local JVM oracle on macOS arm64 (Temurin 21.0.1, Clojure 1.12.5) passed fresh nonce, read-only replay, missing and corrupt marker, foreign ref, and CAS-loser cases. A separate JVM opened an Otehon Forest group whose canonical nonce marker and receipt ref were published in one WAL frame, with the Forest writer set to a nonexistent path: replay returned false and the store root stayed unchanged. With the prior nonce-store implementation, the same read failed attempting to access the missing writer before it reached the nonce ref.
