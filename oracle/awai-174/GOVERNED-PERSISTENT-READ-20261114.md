# Persisted nonce governed read (2026-11-14 UTC)

`read-persistent!` and its Promise variant compose existing capability validation, persisted-basis admission, the canonical receipt sink and `nonce-store/consumer`. They derive a canonical scope CID from `:tenant`, `:principal`, `:graph` and `:authority/epoch` in the request; an extra caller-supplied scope in the nonce configuration is refused and the request's old nonce callback is replaced. Consequently the same nonce is a distinct key in a different scope or epoch. The request record itself has no signature field: the host must authenticate its principal and produce the authority decision, clock and basis verifier; this adapter does not establish identity or trust from the request alone.

Local reference results, macOS arm64, Clojure CLI 1.12.5.1654 and ClojureScript 1.12.42 / Node 26.0.0: the staged repository governed-read suite passed 5 tests / 48 assertions. The new test checks that an invalid basis leaves the backend unchanged, a valid request succeeds, a replay is refused before the evaluator runs again, a caller's previous nonce callback is not used, and an added scope option is refused. The CLJS Promise oracle independently passed rejection, acceptance and replay. Both use fixture authorities and in-memory stores; JVM suite uses the actual causal receipt sink and CLJS uses a fixture sink.

A hosted local reference run used actual Otehon Forest storage, saved signed basis and frontier, the Prolly checkpoint reader, Dango policy and Datalog over fixture data, and the actual causal receipt sink. An invalid fixture signature was refused without advancing the receipt/nonce store; the accepted request wrote receipt `bafyreifakvfs3qgb4htpqlhrbui6h4r3uqz2dylfgzn6tqsuugn3yxifva`. A fresh JVM called `read-persistent!` again with the same request and observed `:nonce-replayed` before authorization/evaluation/receipt; the root was unchanged, and the saved receipt CID and Ed25519 fixture signature verified. The request scope was derived by the candidate API, not chosen by the fixture. Keys, policy data, principal authentication and clock remain fixtures. Forest and frontier stores are separate, without cross-store transaction, durable clock, rollback protection or distributed fencing. No nonce retention/GC is implemented. A crash after nonce CAS can consume the nonce without returning a result; retry is rejected. Existing unbound APIs are not migrated automatically.
