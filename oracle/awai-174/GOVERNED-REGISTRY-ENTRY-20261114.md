# Registry-bound persistent governed read, 2026-11-14

`read-registry-persistent!` and its Promise-aware sibling compose the scoped registry adapter with the existing signed-basis verifier, persisted frontier, nonce consumer and canonical causal receipt sink. The basis config cannot supply a `:verify-entry!` override and verification config cannot substitute its own signature callback. The host still authenticates the principal and owns the registry, issuer authorization, cryptographic implementation, clock, policy, proof location, checkpoint and storage. This is an explicit entry point; it does not replace or silently redirect the deliberately unguarded `kotobase.core` API.

On Clojure CLI 1.12.5.1654, locally staged `.cljc` source and adapted `clojure.test` namespaces `governed-read-test`, `signed-basis-keys-test` and `execution-keys-test` passed 13 tests / 97 assertions. The tests reject attempted basis/signature verifier overrides before fetching proof or executing work. This is a local reference, not the full project suite, CI or Native.

The new synchronous entry was exercised using actual Otehon Forest storage, a persisted fixture frontier and signed proof, Prolly checkpoint reader, Ed25519 test keys, fixture Dango policy, Datalog, persistent nonce and causal receipt sink. A corrupted signature and separately a duplicate-key registry were each refused at `[:basis]` before authorization, evaluation or receipt, with unchanged store root. A valid request yielded the expected rows and persisted receipt `bafyreifakvfs3qgb4htpqlhrbui6h4r3uqz2dylfgzn6tqsuugn3yxifva`; a fresh JVM refused replay at `[:basis]`, kept the root unchanged and verified the receipt CID and test-key signature.
