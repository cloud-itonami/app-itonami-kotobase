# Guest-created GiB file, linked receipt, and reboot readback — 2026-11-15

A dedicated Ubuntu 26.10 ARM Lima guest created the input, wrote it with the Otehon large-file writer, published a linked governed receipt, then was stopped and started. A fresh JVM process reconstructed and verified all 1,024 chunks after the reboot, with the writer executable deliberately unavailable. This is a hosted integration experiment, not Native qualification or production authority.

- Source: awai-os `34cae28e584dc82f749613053952a4c23db696bd`, Kotobase `c57ff9b53367192578aca58e6efcb1417ec1d3e2`; guest uses copied sources and fixture support as in `LINKED-GOVERNED-GIB-GUEST-REBOOT-20261115.md`.
- Input: 1,073,741,824 bytes, synthetic sparse file mostly zeros with deterministic chunk markers; source SHA-256 `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. This is not representative compression or throughput evidence.
- `gib_actual_writer.clj` wrote 64 Packs, logical manifest `bafyreidk3dxbsrqaocvdhfr624j4n75v6ddgmyfgkyu24z3lirlg5aj4g4`; its reported writer elapsed time was 29,595 ms. Forest 0.39.0 x86-64 ran on ARM through QEMU user, with `QEMU_GUEST_BASE=0x800000000000`; JVM was OpenJDK 21.0.13.0.3.
- The hosted fixture published three linked receipt records after checking the signed location, request and every file chunk. The Datalog result was one fixture row and nonce replay was rejected. The location and receipt use fixture keys, trust, policy and clock; the authority verification callback in this fixture is permissive. They are not production policy evidence.
- Before reboot a SHA-256 manifest covered 141 files across file and receipt stores, guest source copies, basis and frontier; a separate hash covered the full input. After reboot all checks passed. Guest boot ID changed from `a6d7739a-a1ca-4656-9347-80fa356c4469` to `1d08a761-875c-49a7-84bb-057d7d1341d3`. The first task-data operation after restart was the separate reader, which verified the signed location, all 1,024 chunks and the source SHA; altered location and wrong request were rejected.
- Evidence archive, copied from guest and independently hashed on host: SHA-256 `915e0e3a9de0272549755560b3a2dc7480afabd52026f46be07d5b92d41135bc`. Archive and guest test data are retained as task evidence.

The file store, signed basis/frontier and receipt store are distinct: this does not prove an atomic publication across them. Basis/frontier originated on the host; the file and linked receipt were produced inside the guest. The reboot clears guest OS cache, not necessarily host cache; there is no real power-loss or independent-node claim. The linked Datalog row is not a query over this file. Full production authority, Native Forest I/O, multiple-Pack product writer integration, and failure/recovery coverage remain open.
