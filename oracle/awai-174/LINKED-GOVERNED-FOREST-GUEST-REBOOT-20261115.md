# Linked governed Forest read after guest restart, 2026-11-15

The host-created linked governed Forest store from `LINKED-GOVERNED-FOREST-20261115.md`, its signed-basis/frontier fixture inputs, candidate source overlays, reader and pinned reference jars were copied to a new dedicated Ubuntu 26.10 aarch64 Lima VZ guest. The store includes the two-Pack publication, not its 132 MiB temporary writer stage. On guest OpenJDK 21.0.13.0.3 / Clojure 1.12.5, a fresh JVM read the published ref, three receipt records, fixture link signature and attachments successfully. The reader used a nonexistent Forest writer tool path; it did not perform Forest writes.

After `sync`, `limactl stop awai-linked-recovery-174` and `limactl start awai-linked-recovery-174`, the guest boot ID changed from `839071ef-61b5-4d4e-9761-4506b852607d` to `0d8b374c-f286-4c2d-9f05-7fea8081f7ab`. A manifest of 1,594 copied files had SHA-256 `60316fb7c07be58d11b16d090723fd3a9b52ce250cd6e7605d51065bd2820723` and verified both before and after the post-restart fresh-JVM read. The read again returned `:ref :verified`, `:records 3`, `:link :verified`, `:attachments :verified`, `:pass true`. The guest evidence archive SHA-256 `91d4d3893c437c3d437420a66a50309c180e0da274991280aa04d31239465fbb` was copied to task scratch and matched. Source revision was `066adfcbd23dfc43eb9c508408537af70867a80b`; the guest manifest covers the actual copied source and jar bytes. The existing signed fixture inputs and classpath follow the preceding evidence.

The guest was newly created from Lima's cached, digest-pinned Ubuntu image. Apt retrieved approximately 23 MB of package indexes and 46.8 MB of packages to install the headless JRE and dependencies, using approximately 207 MB of additional guest disk. The earlier `awai-native-forest-531` guest remained separately preserved; its start timed out while guest SSH refused connections.

This demonstrates a guest stop/start and loss of that guest's page cache for a host-created store. It does not show guest-side write-before-reboot, a new governed Datalog query after reboot, host cache eviction, physical media power loss, Native execution, or production trust. Fixture keys, policy, clock and authority remain in use. The guest and source data are retained.
