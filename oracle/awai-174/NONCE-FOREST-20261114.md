# Scoped persistent nonce consumption (2026-11-14 UTC)

`kotobase.nonce-store/consumer` gives `authority-window` a host-configured nonce consumer. It hashes the canonical scoped key into a ref name, verifies a canonical immutable marker after storage, and performs nil-to-marker CAS. A successful CAS consumes the nonce; an existing marker refuses it. An invalid/missing marker or malformed CAS acknowledgement fails closed. The marker contains the derived key CID rather than raw nonce text. A caller must bind `scope` consistently to its authority, tenant and principal.

The adapter validates the declared ref profile. A `:single-writer-ref` backend requires an explicit `:single-writer? true` and real external exclusivity; the boolean alone does not provide fencing. A failed/ambiguous CAS may consume a nonce without returning rows, and retry must be treated as a replay. A restored or malicious backend, deletion of refs, compromised scope selection and a lying provider cannot be detected. No nonce expiry, GC, distributed consensus, persistent anti-rollback anchor or exactly-once result delivery is provided. One ref per nonce grows indefinitely; capacity and retention require separate design before production use.

On macOS arm64 with Clojure CLI 1.12.5.1654, JVM reference tests passed 2 tests / 11 assertions including scoped replay, concurrent CAS and storage failures. ClojureScript 1.12.42 / Node 26 passed Promise replay, scope and CAS race checks. An actual Otehon Forest backend with explicitly single-writer fixture accepted a nonce once, refused it on replay, then a fresh JVM reopened the store and continued to refuse that nonce while accepting a different scope and a new nonce. This is process restart, not OS cache loss.

A separate hosted composition connected this exact consumer to `read-bound!` with the saved signed-basis/Forest frontier, actual Prolly checkpoint, Dango policy and Datalog implementation over fixture data, and the canonical causal receipt sink. The saved frontier and receipt/nonce stores are separate and not one atomic transaction. Test keys, scope, authority, clock and query data are fixtures; this is not a configured production caller or Native qualification.
