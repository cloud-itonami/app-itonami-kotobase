# Registry-scoped atomic governed read — 2026-11-15

`execute-registry-bound!` composes the existing `execution-keys/verifier` with the request-bound synchronous hosted atomic path. It refuses a caller-supplied `:verify` instead of replacing it. The verifier selects the declared key by record role, tenant and epoch, checks the exact signature envelope and algorithm, and invokes the host's cryptographic verifier. The host must authenticate the registry, request identity, epoch/time, physical root and nonce domain; this wrapper does not provision keys or independently establish authority.

Local one-off OpenJDK Temurin 21.0.1 controls used real Ed25519 fixture signatures and the registry verifier. Correct role/tenant/epoch/key succeeded; wrong tenant, epoch, role, key ID and modified signed payload failed before the mocked evaluation/publisher, and an explicitly supplied verifier was refused. These controls isolate composition; their governed executor is a test double.

The separate hosted 1 GiB oracle invokes the real governed path, actual Dango/persisted Prolly-policy query, canonical receipt sink and Awai bound multi-Pack writer. Execution-manifest and receipt signatures use a versioned envelope and the real registry verifier. A deliberately disabled registry refused an execution before evaluation or publication with root unchanged. An injected publisher failure also left the root unchanged; separately published allow/deny receipts and nonce replay refusal passed. Both physical groups, catalog bindings, receipt refs and nonce refs were recorded in their respective four-put WAL frames. A fresh JVM with source and writer unavailable reverified both signed receipts through the registry, signed basis, policy and 1,024 chunks in each bound group. The issuer and executor roles use the same fixture key, explicitly registered for each role; this is not proof of production key separation. The independently signed data basis still uses the earlier fixture verifier.
