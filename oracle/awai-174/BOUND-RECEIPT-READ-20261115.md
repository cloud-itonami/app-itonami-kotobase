# Receipt decoding over a bound read-only block port — 2026-11-15

`receipt-at-query` factors the existing canonical receipt structure checks into a pattern-query entry point. Existing `receipt-at` still resolves exactly the requested commit using `core/at-cid` and delegates to the same checks. The new entry does not authenticate the query port, commit, rows, identity or visibility; its caller must bind the port to the exact verified immutable commit and enforce authorization. It does not add a second receipt format or a Native runtime.

The hosted fixture composes Awai OS `388b47c`'s read-only bound Forest block port with the existing Kotobase peer `hydrate-chain` and `q` at each receipt's exact commit. Thus receipt transaction/header/record blocks are fetched only from that receipt's bound group without pretending that the block port can write or perform ref CAS. The existing ref store supplies the commit CID; the host must authenticate its root and prevent concurrent mutation/GC. Fixture visibility is `(constantly true)` and authority, key, policy and clock are test inputs. The Prolly/Datalog file query uses the corresponding bound block port too.

A local comparison on the preserved signed allow receipt produced the same proof as the legacy `receipt-at`; empty header, duplicate attribute and missing linked records were rejected. A non-commit CID was refused by peer hydration. The existing published receipt sink also still rejected an injected missing nonce-ref response against a real prior receipt. A separate hosted fresh JVM reverified both bound receipts and both complete 1 GiB groups with original source and writer unavailable. Input is mostly zero; host read was 116.82 s / 738,820,096 bytes maximum RSS, one warm-cache sample with other work running, not a performance gate.

The pattern-query port is trusted: it can fabricate rows unless its caller verifies the commit and provider. This fixture uses real peer code but does not establish a production authenticated root, distributed authority, Native execution, host-cache loss, power-failure durability, ClojureScript execution or deployed integration. The ref and nonce selection still use the hosted backend and are not an independent witness.
