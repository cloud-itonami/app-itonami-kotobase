# Explicit provisional receipt transaction, 2026-11-14

`prepare-execution-receipt` validates an execution receipt and derives the same canonical causal transaction data and receipt identity used by the normal sink. It does not access storage, create a commit, or return `:receipt/durable?`; the caller must publish and read back before issuing an acknowledgement. The existing `execution-receipt-sink` keeps its durable readback behavior. This supplies a contract-safe boundary for a staged put/get path without declaring volatile blocks to be a durable `IBlockStore`.
