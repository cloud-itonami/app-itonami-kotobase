# AWAI-174 frontier store hosted oracle, 2026-11-14

The opt-in adapter reads a frontier block through `IBlockStore` and `IRefStore`, requires bounded canonical bytes and their CID, invokes `engine.frontier/accept-head`, rereads the stored block, and advances the ref by conditional publication. The verifier is injected; these tests use a synthetic verifier, not cryptographic signatures. Explicit initialization is TOFU. Storage rollback, ref deletion, and a dishonest backend are outside this guarantee. A failed CAS may leave an unreferenced immutable block. This unit does not connect the adapter to the product query admission path.

On macOS arm64, using local staged `.cljc` sources including Kotoba `cc94fa4513382cbd9411ec67805dd5feccb851e2` (draft PR #1339), JVM Clojure 1.12.5.1654 / Java 21.0.1 ran `frontier_store_test.clj`: 3 tests, 16 assertions, no failures or errors. Cases include explicit initialization, read/advance, rollback, wrong database, failed signature callback, missing or corrupt block, noncanonical bytes with matching CID, failed block write without ref publication, and a competing CAS. Compiled ClojureScript 1.11.132 / Node v26.0.0 ran `frontier_async.cljs` against Promise-returning storage methods and passed initialization, read, advance and rollback rejection.

The staged host reader quotes namespace export attribute forms as needed. Source staging and test output are retained under `.agent-output/frontier`; this is not an exact dependency-resolution, native artifact, independent-process durable-store, production signature, or anti-rollback qualification. The normal tools.deps checkout of the draft revision was interrupted during a low-disk episode; its managed gitlibs metadata was not altered or removed afterward, and normal dependency resolution needs a clean environment. The draft dependency must be merged and pinned to a qualified revision before product integration.
