# Canonical nonce preparation and non-reserving preflight — 2026-11-15

`prepare-marker` computes the existing bounded canonical key/ref and marker without storage effects. `available?` reads that ref and, if present, verifies the stored marker before returning false. A true result is only an observation: it can become stale immediately and is not authorization or a reservation. A host using it must recheck the absent nonce ref atomically with the exact marker and receipt before releasing a result. The existing consuming API uses the same primitives and retains its put/readback/CAS behavior.

On macOS ARM with Temurin 21.0.1 / Clojure 1.12.5, the local one-off JVM oracle `nonce_existing_marker.clj` passed non-writing preflight, fresh consume, read-only replay, missing/corrupt marker, wrong ref and CAS-race refusal.
